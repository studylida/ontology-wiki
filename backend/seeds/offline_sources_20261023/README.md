# 문헌 기반 오프라인 시드 (2026-10-23)

이 디렉터리는 `sources/`의 129개 Markdown을 읽고 작성·검토한 시드이다. 외부 모델 API 응답을 수집한 기록이 아니며 생성 방식은 `codex-offline-source-review`이다. 원문은 수정하지 않았다. 원문 해시는 실제 파일 바이트를 기준으로 하며, 문자 수는 Python UTF-8 텍스트 읽기의 개행 정규화 기준이다.

`manifest.json`은 문헌 목록·해시, 개념 분류·별칭, 문헌 간 ID 통합 판단과 적용 순서를 담는다. `documents/NNN.json`은 문헌별 추출 기여와 전체 읽기 기록·검토 메모를 보관한다. 정의·관계·사례는 제공된 원문 범위에서 작성했다. 수치가 없거나 인용·줄 번호가 없다는 이유로 내용을 탈락시키는 조건을 추가하지 않았다.

기술 정의 없이 개요·영상 소개·관련글 링크만 있던 092·102·104·106·107은 개념을 꾸며 넣지 않고 빈 결과와 사유를 기록했다. 129건 검토, 124건 적용 대상이다. 원 논문 전문, DOI 실재, 링크된 영상, 현재 제품·양산 상태는 외부 확인하지 않았다. 자료 자체의 불명확한 표현과 서로 다른 비교 조건은 문헌별 메모·사례 주의사항으로 남긴다.

## 새 DB 만들기

저장소 루트에서 기존 Python 가상환경을 사용한다. 대상 DB 파일의 부모 디렉터리는 먼저 만들고, 아직 존재하지 않는 새 파일 경로를 명시한다. 운영 DB 경로를 전달하지 않는다. 스크립트는 기존 파일을 덮거나 삭제하지 않는다.

```powershell
.venv/Scripts/python.exe scripts/import_offline_seed.py --seed-dir backend/seeds/offline_sources_20261023 --database C:/path/to/new-wiki-seed.sqlite3 --report-dir C:/path/to/build-report
```

내용은 기존 `source_service.prepare_preview()`와 `apply_extractions_to_wiki()`를 통해 적용한다. source hash·DTO·분류·전체 문서 처리·참조와 적용 트랜잭션을 유지한다. 동일 문헌 재적용은 0건 변경임을 확인한다. 별칭은 기존 `concept_repo.merge_aliases()`에서 보존 병합한다. 사례 해설은 문헌별 작성본을 기존 `case_explanation_service.generate()`의 입력 서명·공개 판정·조건부 저장 경로로 저장하며 원문 이력에는 넣지 않는다. 외부 모델 호출은 이 CLI 프로세스 안에서 차단하고 정상 서비스 설정은 바꾸지 않는다.

중간 실패한 DB는 진단을 위한 부분 산출물로 남는다. `build-report.json`의 `complete: true`, `externalModelCalls: 0`과 무결성 결과를 확인한 빌드만 사용한다. 전체 재생성이 필요하면 다른 새 DB 파일을 지정한다. 새 사용자·가짜 검토 티켓·챗 이력·시범 개념을 복사하지 않는다. 제품 앱을 별도 검증 서버로 띄우면 기존 시작 절차의 테스트용 기본 계정이 격리 DB에 추가될 수 있다.

## 읽기 전용 검증

```powershell
.venv/Scripts/python.exe scripts/verify_offline_seed.py --database C:/path/to/new-wiki-seed.sqlite3 --seed-dir backend/seeds/offline_sources_20261023 --report C:/path/to/api-verification.json
```

검증기는 읽기 전용 SQLite 연결과 원래 제품 GET 라우터로 모든 개념 상세·문헌 미리보기·대표 관계 API를 확인한다. 빈 추천과 전체 등록명 검색의 결과 ID, 관계 검토 이력에 반영된 연결도 확인한다. 모델 호출이 없고 지식 테이블의 전후 서명이 같은지 확인한다. 실제 원문 파일 해시도 재확인한다.

검증한 통합 결과는 개념 494개, 사례 215개, 관계 edge 339개, 근거 1,614개이다. 공개 원문 적용 이력과 현재 사례 내용·근거가 확인된 215개 사례 모두 쉬운 해설을 저장했다. 수치가 없는 82개 사례도 포함하며 가짜 사양을 채우지 않았다. 공개 판정은 제목·배지·본문·주의사항·사양 전체가 적용 이력과 같은지 확인하고 최신 승인 티켓의 비공개 의도를 우선한다. 비공개 사양·출처 불명 legacy 사례는 계속 보호한다. 미등록 관계 대상 7건은 `build-report.json`에 기록하며 등록된 개념으로 가장하지 않는다. 이들은 기존 관계 DTO의 미등록 표시를 따른다.

관계 화면은 상위·하위 분류와 소속·구성 요소를 모두 표시한다. 규모별 연결은 실제 등록 관계의 두 단계 이웃을 규모별로 모으며 구성·분류·선후·대안의 종류와 방향을 보존한다. 물리 소속이 아닌 관계를 물리 포함 사다리로 표현하지 않는다. 연구 아카이브의 원문 명칭·메커니즘으로 확인한 누락 분류 관계를 보강했다.

## 미연결 285개 개념의 원문 관계 재검토

기존 등록 관계의 이웃이 없던 285개 개념을 대상으로 관련 원문 83개를 다시 읽었다. 개념별 판단·읽은 문헌 해시·근거·보류 이유는 `relation-review.json`에 기록했다. 132개 제안 중 기술과 제품, 공정과 장비의 의미가 혼동될 수 있는 4개를 보류하고 35개 문헌에 128개 관계 기여를 추가했다. 같은 연결을 지지하는 두 문헌의 기여가 있어 DB의 고유 edge 증가는 127개이다. 등록 대상만 연결하며 단순 용도·함께 언급·수치 누락을 이유로 관계를 강제하거나 설명을 삭제하지 않는다.

최종 판단은 자체 관계를 보강한 114개와 추가 연결 근거가 부족한 171개이다. 후자 중 다른 개념의 관계 대상으로 연결된 경우도 있어, 전체 등록 관계에 참여하는 개념은 209개에서 342개로 늘고 이웃이 없는 개념은 152개 남는다. 기존 494개 정의·분류·원리·한계, 215개 사례와 해설, 근거 1,564개는 이전 격리 DB와 동일하게 보존했다.

지식 관계 뷰는 실제 소속·분류·구성·하위 종류를 먼저 표시하고 관계 방향과 사유를 보여준다. 전후 공정이나 대안이 없으면 빈 패널은 숨긴다. 검색 바로가기는 기존 Spotlight API가 반환한 실제 등록 개념을 사용하며 표본 ID를 하드코딩하지 않는다.

## 대상 규모 전수 검토와 원리 표시

등록 494개 개념의 현재 정의·원리·원문별 분류 제안을 전수 검토하고 관련 원문 41개 파일의 기록된 범위를 재대조했다. 전문과 일부 절 확인은 `scale-review.json`에서 구별한다. 명확한 오분류 98개만 현재 확정 규모로 정정했으며 344개는 유지하고 경계가 모호한 52개도 사유를 남겨 기존값을 유지했다. 분류 판단은 개념 자체의 대상에 근거하며 큰 장비나 산업에 쓰인다는 이유로 규모를 올리지 않는다. 기존 1~5 정수 계약과 분야·공정군은 유지했다.

집적회로·CPU·SoC·HBM·칩렛 같은 칩·패키지 구조는 Scale 2, FEOL·MOL·BEOL과 패키징 방법은 Scale 3, 광원·노광기·장비 부품은 Scale 4로 구별했다. 모든 문헌의 원래 제안은 문헌 JSON에 보존하고 `manifest.json`의 현재 확정값과 기존 통합 결정의 selected만 맞췄다. 이전 규모와 정정 근거는 `scale-review.json`에 남는다.

규모 안내는 실제 길이 경계가 아니라 대상 범주이다. Scale 2 안내에 회로·패키지를, Scale 4에 시스템을, Scale 5에 운영을 명시하고 탐색·관계·추천·추출 안내를 일치시켰다. 원리 목록은 문헌마다 다시 시작한 step 번호가 전체 공정 순서로 오해되지 않도록 Step 배지만 제거하고 기존 제목·본문·수식·순서와 저장값을 보존한다.

범위 밖: 운영 DB 적용·서버 전환·배포, PostgreSQL 실행 검증. SQLite 외래 키·무결성 및 기존 원문·해설 회귀 검사는 별도 격리 DB에서 수행했다.
