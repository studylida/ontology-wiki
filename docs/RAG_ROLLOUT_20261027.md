## 적용 경로

Docling은 격리된 고정 버전 실행 환경에서 문서 구조와 표·조건을 추출한다. 원본 바이트, 구조 JSON, 위치 지도, 구간별 정확한 범위·해시를 별도로 저장한다. Cu 논문의 숨겨진 과거 원고 객체는 보이는 페이지를 PDFium으로 렌더링하고 전체 페이지 OCR을 적용해 분리했다. 상세한 프로필·검증 범위는 [Docling 문서](DOCLING_INTEGRATION.md)를 따른다.

기존 PostgreSQL·pgvector 및 문자 검색에서 넓게 후보를 모으고, CrossEncoder가 최대 60개 후보를 한 번 재정렬한다. 최종 직접 구간은 5개이며 출처 계보당 2개 한도를 적용한다. 선택된 결과 주변의 실험 조건은 남은 문맥 예산에서 함께 읽는다. 명시적인 수치 요청은 질문에서 감지한 전력·온도 등의 측정 항목을 재정렬 입력에 강조한다. 특정 논문·기술명·정답 수치는 검색 규칙에 넣지 않았다.

LightRAG는 Extended에서 관계 기반 추가 후보를 찾는다. 자체 설명을 원문처럼 인용하지 않고 저장된 실제 구간 ID와 내용 해시로 연결한 뒤 공통 재정렬에 합친다. 현재 권한·승인·활성 판본·메타데이터가 구축 snapshot과 일치해야 사용한다. 전체 구축 성공 전에는 이전 활성 인덱스를 교체하지 않는다. 상세한 보존·재개 계약은 [LightRAG 문서](LIGHTRAG_INTEGRATION.md)를 따른다.

RAGChecker는 별도 평가 환경에서 실행한다. 판정 개수 누락을 중립 판정으로 채우지 않고 실패로 남긴다. 이 평가기는 제품의 매 질문마다 실행하는 경로가 아니다.

## 답변과 출처 표시

`자료에서 정리한 관점` 블록은 답변 화면과 생성 근거에서 제외하고 저장 데이터·API는 보존했다. 기술 내용을 직접 설명하고, 자료명·발행처를 풀어 쓰는 설명은 사용자가 문헌별 주장이나 출처 소개를 요청한 경우에만 작성하도록 했다. 일반 원리와 특정 실험을 문단으로 나누고 실험 목적·시편·조건·결과·지표 의미를 연결하도록 했다. 요청하지 않은 지표의 부재나 사용하지 않은 연구에 대한 방어 문장은 답변에 추가하지 않도록 했다.

출처는 명시적으로 확인한 계보별로 묶고 자료 형태·판본·구간 수를 구별한다. 근거 구간은 기본적으로 접힌다. 생성 모델에는 짧은 E키를 제공하고 실제 인용 ID로 정확히 복원한다. 미확인 ID는 정상 완료하지 않으며 중단 전 받은 본문·사용량은 보존한다. 취소 뒤 도착한 사용량은 집계하지만 늦게 도착한 본문은 추가하지 않는다.
