# 대화 중심 프런트엔드

이 문서는 `frontend/`의 구현 책임과 실제 동작을 설명합니다. API의 공통 계약은 [design/CONTRACT.md](design/CONTRACT.md)를 함께 읽습니다. 이전 네 개 탭, 독립 위키 탐색 화면, 비교 전용 화면, 플로팅 챗봇 및 주장별 공용 지식 편집 UI는 교체했습니다. 과거 구현은 Git 이력으로 남으며 새 앱은 이전 코드 경로를 호출하지 않습니다.

## 실행

```sh
cd frontend
npm ci
npm run dev
```

개발 주소는 `http://127.0.0.1:5173`입니다. `/api`를 기본 `http://127.0.0.1:8000`으로 전달합니다. 컨테이너 구성 등에서 필요하면 `OW_API_PROXY_TARGET`으로 개발 프록시 대상만 바꿀 수 있습니다. 별도 배포의 API 기준 URL은 `VITE_API_BASE_URL`로 지정합니다. 이 값은 공개 클라이언트 구성입니다. 공급자 키나 비밀 값은 Vite 환경 변수로 전달하지 않습니다.

```sh
npm test
npm run build
```

빌드는 TypeScript 검사와 Vite production build를 함께 수행합니다. `dist/`는 빌드 산출물입니다. 앱의 로그인 폼은 서버가 발급한 세션 토큰만 `sessionStorage`에 저장합니다. 개발 계정 생성은 백엔드 부트스트랩 절차를 사용합니다.

## 책임과 파일 위치

| 책임 | 구현 | 경계 |
| --- | --- | --- |
| View | `src/views/`, `App.tsx` | 사용자 이벤트, 접근 가능한 버튼·폼, 현재 상태 표시. 공급자 호출과 영속화 규칙을 담지 않습니다. |
| Controller | `src/controllers/` | 화면 상호작용, 명령 실행, 비동기 취소·경합·복원. React hook으로 구현합니다. |
| Service | `src/services/` | 요청 구성, 대화 상태 전이, 문헌 전달, 출처 그룹 구성, 표시용 순수 변환. |
| Repository | `src/repositories/` | 인증된 HTTP, 실제 SSE 프레임 읽기, 브라우저 초안 저장. |
| DTO | `src/types/contracts.ts` | API·이벤트·화면 상태의 TypeScript 계약. 실행 단계가 아닙니다. |

별도 계층을 거쳐야 한다는 이유만으로 모든 GET 요청에 무의미한 Service 래퍼를 만들지 않았습니다. 여러 동작을 결합하거나 규칙을 가진 유스케이스는 Service에 두고, Controller의 단순 조회는 Repository를 사용합니다. 파생 표시값은 렌더 시 계산하며 API 부작용을 파생 상태 동기화용 Effect에 숨기지 않습니다. 구독·라우트 복원·폴링은 명시적으로 정리되는 Effect를 사용합니다.

라우트는 `useRoute`가 해시 경로를 해석합니다. 첫 버전에 서버 측 라우트 설정을 추가하지 않고 정적 배포에서도 주소 복원이 가능하도록 했습니다.

| 경로 | 화면 |
| --- | --- |
| `#/conversation` | 새 대화 |
| `#/conversation/{id}` | 저장된 대화 |
| `#/research/{conversationId}` | 원래 대화를 가진 외부 조사 |
| `#/personal-wiki/{id}` | 사적인 개인 위키 |
| `#/review` | 권한을 가진 사용자의 문헌 단위 검토 |

## 하나의 대화와 다음 답변 설정

새 대화의 기본값은 위키 모드, Extended 꺼짐입니다. 명시적인 새 대화 버튼은 빈 초안과 기본 설정으로 시작합니다. 기존 대화 이동·복원과 외부 조사 왕복은 해당 대화의 초안, 다음 답변 모드, Extended, 자료·개념·발행처 범위와 스크롤 위치를 복원합니다.

위키/분석 토글과 Extended 버튼은 로컬의 다음 요청 설정만 바꿉니다. 클릭 자체로 검색·모델·저장 요청을 보내지 않습니다. 이미 받은 메시지의 모드는 각 메시지에 남으며 나중 토글로 바꾸지 않습니다. 모델·effort는 서버 실행 구성과 별도 설정 정보에 표시합니다.

다음 상태는 사용자와 대화별 `localStorage` 키에 저장합니다.

- 입력 초안, 다음 모드와 Extended.
- 선택된 개념 ID, 공용 문헌 필터 ID, 현재 대화에서 읽을 문헌 ID, 외부 문헌 첨부 ID, 출처 그룹 조건.
- 실제 조회한 제목·개념명 표시 캐시와 스크롤 위치.

선택의 기준은 ID 배열입니다. 표시용 이름을 별도 선택 상태로 중복 관리하지 않습니다. 이름을 복원하지 못하면 미확인으로 표시합니다. 서버 대화의 `nextSettings`보다 해당 브라우저의 미전송 초안을 우선합니다. 대화 메시지·실행 결과는 서버가 기준이며 브라우저에서 성공 응답을 만들지 않습니다.

## 요청·스트림·복원

`POST /answer-runs`에는 새 `clientRequestId`가 들어갑니다. 응답의 `messageId`는 assistant 메시지 ID입니다. 네트워크 오류로 POST 결과가 불명확하면 같은 ID로 확인·재시도하여 중복 생성 방지를 서버와 공유합니다. 종료된 실패 답변을 명시적으로 다시 요청할 때는 새 요청 ID와 `retryOfRunId`를 사용합니다.

SSE는 인증 헤더가 필요한 `fetch` 스트림으로 읽습니다. 프레임 파서는 분할 패킷, CRLF, 여러 줄 data, 주석을 처리하며 알려진 이벤트와 숫자 seq만 받습니다. `runId + seq`로 중복과 역순 이벤트를 무시합니다. 서버에서 도착한 nonempty 본문 delta를 바로 렌더합니다. 전체 JSON을 기다리는 흐름, 글자 단위 타이핑 연출, 임의의 지연을 두지 않습니다.

연결이 끊기거나 스트림이 EOF로 끝나면 먼저 GET 실행 상세를 읽습니다. 실행이 끝났다면 저장된 결과로 복원하고, 계속 실행 중이면 마지막 seq 이후를 최대 네 차례 재연결합니다. 서버 재시작 뒤 `REPLAY_CURSOR_AHEAD`도 실행 상세로 복구합니다. 인증·접근 오류는 반복 재연결하지 않습니다. 재연결은 새 답변 생성 명령이 아닙니다.

취소 버튼은 서버 취소 명령 후 저장된 실행을 확인합니다. 이미 받은 본문을 남기고 취소·실패·중단 상태를 구분합니다. 종료 후 늦게 도착한 delta로 답변을 다시 성공 상태로 바꾸지 않습니다. 다른 대화로 이동하면 현재 화면 구독만 정리하며 서버 실행을 임의 취소하지 않습니다.

자동 스크롤은 답변 아래에 먼저 도착한 출처·관계 카드의 끝이 아니라, 실제로 생성된 마지막 본문 블록을 따라갑니다. 사용자가 위쪽을 읽으면 자동 따라가기를 멈추고 “최신 응답”으로 다시 합류할 수 있습니다. 새로 복원한 대화에 보관된 스크롤 위치가 없을 때도 본문부터 보이며, 저장된 스크롤 위치가 있으면 이를 우선합니다.

위키 본문은 도착한 Markdown을 핵심 설명, 목적·원리, 사례·조건, 관계, 출처·부족한 부분 순으로 읽습니다. 다 도착하지 않은 제목이나 문장도 이미 받은 텍스트를 표시합니다. 종료 후 제공되지 않은 항목은 제공되지 않았다고 표시합니다. 분석 답변은 같은 안전한 Markdown 렌더러로 설명과 표를 표시합니다.

## 관계·출처·관점

관계 카드의 기본 클릭은 조건과 근거를 인라인으로 펼칩니다. 원문 열기와 후속 질문은 별도 버튼입니다. 후속 질문은 별도의 확인 창에 준비하므로 기존 입력 초안을 덮지 않습니다. 사용자가 전송할 때만 후속 요청을 만듭니다.

인용 렌더러는 서버가 실제로 전달한 citation ID만 연결합니다. `[id]`와 `[출처: id]`를 모두 지원하며 화면에는 출처 목록과 대응하는 번호, 접근성 이름에는 출처 제목을 표시합니다. 내부 passage ID를 읽기용 이름으로 쓰지 않습니다. 코드·기존 링크 안의 문자열은 바꾸지 않으며, 알 수 없는 표기는 평문으로 남깁니다. 단순 인용 문자열 불일치를 이유로 정상 지식 본문을 삭제하지 않습니다.

원문 패널은 열 때 현재 권한으로 원문 판본을 다시 조회합니다. 권한 없는 판본은 본문이나 이전 인용문으로 대체 노출하지 않습니다. 문헌 상태, 판본, 읽은 범위, 출처, 정제 본문을 표시합니다. Markdown frontmatter는 접을 수 있는 파일 메타데이터로 분리해 보이며 원문 저장값을 수정하지 않습니다. 파일 내 `official` 등 자체 표기를 검증 결과로 사용하지 않습니다.

관점 카드는 발행처·실제 주장 주체·적용 조건·확인 상태·근거를 구분합니다. 여러 개념의 카드가 섞였으면 같은 개념에 대한 관점이라고 표시하지 않습니다. 화면 내 필터는 이미 받은 카드의 표시만 바꿉니다. 등록 관점 조회는 명시적인 GET이며 답변 생성과 다릅니다. 선택한 관점 비교도 후속 질문 확인을 거칩니다. 관계의 `is_a`, `alternative_to` 등은 화면용 한국어 이름으로 표시하되 관계의 출발·도착 개념과 방향을 바꾸지 않습니다.

첫 질문에서도 자료 선택 창의 발행처 범위에서 실제 문헌 메타데이터의 `publisherId`를 선택할 수 있습니다. 회사 이름을 하드코딩하거나 본문 언급에서 발행처를 추정하지 않습니다. 그룹별 발행처와 문헌 유형은 AND 조건입니다. 여러 그룹을 선택해도 모드·Extended를 바꾸거나 검색을 즉시 시작하지 않습니다.

실행 상세의 출처별 검색 범위는 서버에 저장된 `retrievalSummary.groupCoverage`에서 표시합니다. 부족한 그룹·조건을 함께 보이며 문헌 수를 의미 정확성 점수로 표현하지 않습니다. 과거 답변도 실행 정보 열기에서 실제 GET 상세를 읽으며 새 생성은 하지 않습니다.

## 문헌 범위의 세 가지 계약

| 요청 필드 | 의미 |
| --- | --- |
| `sourceRevisionIds` | 승인되어 활성 색인에 반영된 공용 검색 범위 축소 |
| `documentContextIds` | 현재 사용자가 읽을 권한이 있는 문헌을 이번 대화에서 직접 활용. 검토 중 문헌 질문에도 사용 |
| `attachmentIds` | 외부 조사에서 확보해 대화로 전달한 자료 |

검토 중 문헌의 “이 문헌에 질문”은 `documentContextIds`에 추가합니다. 아직 일일 색인에 반영되지 않아도 현재 대화에서 읽을 수 있으며 공용 승인이나 권한 검사를 우회하지 않습니다. 자료 추가는 첨부만 하고 답변을 자동 생성하지 않습니다.

## 외부 문헌 조사

한 번의 제출은 명시된 검색 한 번입니다. 자동으로 검색어를 끝없이 바꾸는 루프를 UI에서 만들지 않습니다. 문헌 한 개에 카드 한 개를 표시하고 실제 `readScope`로 메타데이터·초록·부분·전체 확인을 구분합니다. 본문 미확인 자료에는 관련성이나 한계를 판단했다고 쓰지 않습니다.

본문 가져오기는 서버의 실제 fetch 결과를 반영합니다. 새 카드 ID가 반환되면 선택 ID도 갱신합니다. 내용 확보 없이 메타데이터만 있는 자료 전부를 전달하려 하면 설명 가능한 오류를 표시합니다. 일부 자료 실패는 서버 warnings를 보존합니다.

가져오기는 확보한 자료, 검색 질문과 조건을 원래 대화에 연결하고 실제 제출 결과만 알립니다. 현재 구현에서 선택 공개 문헌이 검토 대기로 제출된다는 안내를 가져오기 버튼 옆에 둡니다. 가져오기 성공이 답변 생성이나 공용 승인 성공을 뜻하지 않습니다. 검색·본문 확보·전달의 동시 조작이 서로 다른 선택 결과를 섞지 않도록 제어합니다.

## 개인 위키와 문헌 검토

개인 위키는 대화 응답의 위키 모드와 별개인 사적 기록입니다. 전역 자동 정리 설정과 대화별 자동 정리 허용·제외를 구분합니다. 원메시지 수동 정리 요청의 queued, existing, skipped를 구분하고, 작업 succeeded라도 action이 skipped이면 저장되었다고 표시하지 않습니다.

검색어 입력을 잠깐 기다리는 동안과 실제 목록 응답을 기다리는 동안 모두 조회 중 상태를 표시합니다. 선택한 페이지가 먼저 복원되더라도 목록이 아직 오지 않은 상태를 “저장한 페이지 없음”으로 표현하지 않습니다.

편집은 `expectedVersion`을 사용합니다. 충돌 시 입력을 보존하고 최신 저장 내용을 미리 보여주며, 사용자가 최신 판본을 기준으로 계속 편집할지 선택합니다. 자동으로 새 판본을 덮어쓰지 않습니다. 삭제 되돌리기는 서버가 반환한 삭제 후 버전을 사용합니다. 첫 AI 정리 자체를 되돌려 페이지가 사라지는 응답도 처리합니다. 접근 철회된 원문에서 파생된 페이지는 서버의 마스킹 응답과 안내를 표시하고 편집·후속 질문 본문을 제공하지 않습니다.

문헌 검토는 문헌 판본 단위입니다. 원문·정제 구간과 출처 메타데이터를 미리 보고 승인, 반려, 보류, 철회합니다. 정제 본문 수정은 새 원문 판본을 만들며 이전 원문을 덮지 않습니다. 공용 주장 단위 편집기를 되살리지 않았습니다.

승인 상태와 검색 반영 상태는 별도로 표시합니다. 일일 색인 대기와 관리자 명시 즉시 실행을 지원합니다. 즉시 실행은 선택된 승인 문헌에만 요청합니다. 작업 목록의 실제 상태·오류·취소·재시도를 보여주며 결과 없이 완료를 가정하지 않습니다. 상태 폴링은 편집 중인 메타데이터나 본문 초안을 덮지 않습니다.

## 실행 정보와 비용

실행 정보는 모델, effort, 실제 API 호출 수, 공급자가 제공한 토큰 사용량과 확인 가능한 비용을 표시합니다. 미확인 비용·토큰은 null을 미확인으로 표현하며 0으로 계산하지 않습니다. Fixture는 전역 배너와 해당 답변에 명시하고 실제 공급자 호출과 구분합니다.

요청 Effort와 공급자가 실제 반환한 Effort는 별도로 표시합니다. `usage.requestedEffort`는 요청 구성이고, `usage.effectiveEffort`와 `serviceTier`는 실제 공급자 응답이 있을 때만 표시합니다. 미반환 값은 요청 설정에서 추정하지 않습니다. 서비스 등급도 요청값과 반환값을 구분합니다.

`usage.model`은 검색 임베딩과 생성의 집계에서 `multiple`일 수 있으므로 생성 모델 표시로 사용하지 않습니다. 요청 생성 모델과 공급자 반환 생성 모델을 구분하고, 후자는 `answer_generation` component의 실제 공급자 반환값만 사용합니다. 호출별 상세에서는 생성과 검색 임베딩 각각의 모델·토큰·비용을 확인합니다. 전체 집계의 미확인 값을 개별 호출에서 확인된 값으로 임의 대체하지 않습니다.

`retrievalMs`, `generationMs`, `firstTextMs`, `totalMs`는 서버 기록입니다. 첫 실제 답변 텍스트는 `firstTextMs`로 표시합니다. 브라우저는 이번 창에서 직접 제출한 실행만 전송 시각을 기억하고, 첫 nonempty 본문이 DOM에 반영된 뒤 두 번의 requestAnimationFrame을 거친 관측값을 `/client-metrics`에 한 번 보냅니다. 반환된 `clientFirstVisibleTextMs`를 별도로 표시합니다.

이 클라이언트 값은 정확한 물리적 화면 표시 시각이나 신뢰된 서버 계측이 아닙니다. 복원·SSE 재생·동일 요청 확인 재시도에는 새 관측값을 만들지 않습니다. 계측 업로드 실패를 답변 실패로 바꾸지 않습니다.

## 접근성·안전한 렌더링·모션

실제 button, input, textarea, select, native dialog를 사용합니다. 아이콘 버튼은 이름을 제공하고 상태 토글은 aria-pressed로 표시합니다. 모달은 닫기·Escape·초점 복원을 지원하며 좁은 화면에서는 탐색 메뉴와 원문 패널을 독립적으로 닫을 수 있습니다. 긴 표·원문은 자체 영역에서 스크롤합니다.

생성 Markdown의 raw HTML과 외부 이미지는 렌더하지 않습니다. 외부 링크는 http(s)만 허용하고 새 탭 링크에 noopener/noreferrer를 붙입니다. 키와 원문 전체를 콘솔이나 검증 결과 JSON에 기록하지 않습니다.

모션은 [transitions.dev introduction](https://transitions.dev/detail.html?doc=introduction), [panel reveal](https://transitions.dev/studio.html?lib=panel-reveal), [modal open/close](https://transitions.dev/studio.html?lib=modal-open-close), [accordion](https://transitions.dev/studio.html?lib=accordion)의 공식 패턴 설명을 실제 확인하여 적용했습니다. 중앙 CSS `styles/transitions.css`에 적용한 패턴과 출처를 적었습니다. 제공된 export 코드를 그대로 복사했다는 뜻은 아닙니다. 문맥을 가진 열기·닫기·접기에만 짧은 CSS 이동과 투명도 전환을 사용하고 `prefers-reduced-motion`에서는 줄입니다. 스트리밍 본문을 모션으로 지연시키지 않습니다. [공식 라이선스](https://github.com/Jakubantalik/transitions.dev/blob/main/LICENSE)의 개별 패턴 사용 범위를 확인했으며 별도 런타임·외부 스크립트를 설치하지 않았습니다.

## 검증과 한계

최종 `npm test -- --reporter=json --outputFile=../docs/verification/frontend-tests.json`은 7개 파일의 28개 테스트를 통과했고 `npm run build`도 통과했습니다. 중복·늦은 SSE, 취소 후 delta, 불완전 본문, 모드/초안 보존, 실제 메타데이터 기반 출처 그룹, 인용 연결, 관계 방향, 안전한 Markdown, 개인 위키 판본 충돌·조회 대기, 생성과 임베딩 사용량의 분리, 본문 중심 자동 스크롤을 검증합니다. 단위 테스트는 네트워크 요청이나 유료 모델을 호출하지 않습니다.

이전 Fixture 환경의 검증 기록은 `docs/verification/frontend-browser-result.json`과 `frontend-*.png`에 남깁니다. 인증, 입력·설정 보존, 출처 그룹 선택, API/SSE·저장·복원, 원문 조회, 클라이언트 계측, 모바일 화면, 검토 미리보기를 확인한 이 기록을 실제 외부 생성 모델의 실행으로 바꾸어 설명하지 않습니다.

최신 실제 모델 검증은 [verification/live/frontend-verification.md](verification/live/frontend-verification.md)에 범위와 한계를 정리했습니다. `frontend-live-read-result.json`은 미리 완료된 GPT-6 Luna 위키·분석 답변과 실제 생성·병합된 개인 위키를 GET으로 확인한 결과입니다. 로그인 외 쓰기 요청을 차단한 상태에서 1,233개의 저장된 본문 delta를 복원하고, cursor 이후 재생·출처 원문·관계 펼침·초안 보존·출처 관점 비교 준비·모드별 메시지 복원·390px 모바일 화면을 확인했습니다. 개인 위키는 판본 2와 두 원메시지 연결을 확인했습니다. 이 조회 검증은 생성·임베딩·개인 위키 재정리 호출을 추가하지 않았습니다.

`frontend-live-stream-result.json`은 삼성·SK hynix의 공개 문헌 3개만 선택한 별도 대화에서 실제 생성 1회와 질의 임베딩 1회로 검증한 결과입니다. Extended와 개인 위키 자동 정리를 끈 상태에서 실제 본문 수신, 실행 중 새로고침, 같은 실행 재연결, 취소, 229자 부분 답변의 영속 복원을 확인했습니다. 새 생성 POST는 1회, 브라우저 최초 표시 계측 POST도 1회였으며 재로딩으로 늘지 않았습니다. 서버 첫 본문은 4,990.26ms, 브라우저 DOM 반영 후 관측값은 5,107.80ms였습니다. 한 사례의 관측값이며 지연 성능의 일반적인 보장으로 사용하지 않습니다.

취소한 생성의 최종 사용량은 반환되지 않아 총 토큰·총 비용을 미확인으로 유지했습니다. 확인된 임베딩 비용 추정분 `knownCostUsd`만 별도로 남고 전체 비용 `costUsd`는 null입니다. 완료한 실행의 비용도 공개 단가와 반환 사용량에 따른 추정치이며 청구서 확인값이 아닙니다.

실제 스트림 검증 뒤 본문 아래의 긴 출처 목록을 따라가던 스크롤 문제를 수정했습니다. 수정은 DOM 회귀 테스트와 이미 저장된 실제 취소 답변을 새 창에서 복원한 `frontend-live-13-partial-body-in-view.png`로 확인했습니다. 이 마지막 스크롤 수정 뒤 새로운 유료 스트림을 다시 실행하지 않았으며, `frontend-live-10`·`11` 이미지는 수정 전 실제 실행 기록입니다.

이 검증은 구현된 UI와 저장·재연결 경계를 확인합니다. 문헌의 공식성, 생성 내용의 전체 의미 정확성, 외부 문헌 검색 품질, 다양한 네트워크 장애·운영 부하·접근성 전체 준수를 입증하지 않습니다. 출처 관점 선택과 후속 질문 준비는 확인했지만 해당 자료에서 서로 다른 개념이 함께 나와 제공되지 않은 “등록 관점 조회” 버튼의 실제 GET은 이 브라우저 실행에서 확인하지 않았습니다. 관련 이벤트 경계는 단위 테스트에서 별도로 확인합니다.
