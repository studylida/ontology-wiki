# 문헌 조사실 검색·관련성 설명

## 목적과 책임

사용자가 문헌 내용을 모르더라도 어떤 자료이며 질문의 어느 부분에 왜 도움이 되는지 판단할 수 있게 한다. 검색 결과 수나 단어 일치 점수를 관련성의 보증으로 표시하지 않는다.

API는 입력·키 전달·응답 계약을, `research_service`는 원래 비교 맥락의 복원·검색·발췌 구성·중복 통합·판정 검증·저장을, `research_discovery_agent`는 기존 Gateway를 통한 계획·우선순위 선별·평가 생성을 담당한다. Repository는 등록 자료·원문 파일·Crossref·공개 HTTP I/O와 조건부 저장을, `research_content`는 HTML/PDF 텍스트 추출과 읽을 구간 선정을 담당한다. 프론트 Controller는 질문 해석·필요한 확인·문헌 선택·세션 복원·재개를 소유하며 View는 결과와 근거를 표시한다.

## 실행 계약

기존 `POST /research/clarify`가 `searchPlan`을 반환한다. 계획은 원래 질문·해석·가정·검색어·확인 질문·ready/needs_clarification/source_only 상태다. 뜻이 분명하면 바로 기존 `/discover`로 진행한다. 브라우저 계획은 검색 조건일 뿐 권한이나 문헌 사실의 근거가 아니며 비교 맥락은 서버에서 복원한다. `/discover` 직접 호출은 서버에서 계획을 생성한다.

`ResearchEvidenceFeedItem`에 `readSegments`와 nullable `assessment`를 추가한다. 평가는 included/deferred/excluded 판단·문헌 소개·포함 이유·활용점·한계·근거 구간 ID로 구성한다. 제목·DOI·URL·발췌는 검색 결과에서 가져오고 모델이 덮어쓰지 못한다. 등록 `quote`는 절단하거나 생성문으로 교체하지 않는다. 모델에 제공한 일부 구간과 전체 확보 발췌를 구분한다.

검색 범위는 기존 등록 자료·원문과 Crossref다. 검색 결과의 출판사·DOI·본문 링크 및 페이지의 citation_pdf_url에서 공개 HTML/PDF 내용 확보를 시도한다. HTTPS 443·공개 IP만 허용하고 DNS 주소를 연결 시 고정하며 리디렉션마다 다시 검사한다. 인증·쿠키를 전달하지 않는다. 응답은 5MB, PDF 추출은 별도 프로세스 10초·20쪽·10만 자로 제한한다. HTML의 문서 자체 제목/DOI 메타데이터, PDF 첫머리 제목으로 문헌 귀속을 확인한다. OCR·로그인·유료벽 우회·일반 웹 검색은 포함하지 않는다. 초록·원문 일부 구간만 읽었다면 그 범위와 출처·확보 기록을 표시한다. 동일 DOI URL은 하나의 문헌으로 통합하고 등록 출처의 ID와 발췌를 우선한다.

실행 예산은 요청당 검색 최대 4회·150초다. 검색 1회당 후보 30개와 화면 첫30개는 세션 전체 저장 상한이 아니다. 새 검색으로 찾은 문헌은 계속 통합한다. 제목 선별은 최종 관련성 판단을 대신하지 않는다. 상세 평가는 최대4문헌·합계12000자·40초로 나누며 문헌당 실제 입력은6000자다. 내용 확보는 요청당 최대4문헌·문헌당2주소·22초 내에서 시도한다. 평가에서 나온 보완 검색어를 우선하고 성공한 검색어는 반복하지 않는다. Crossref 캐시와429 대기를 사용하며 실패 검색·일시 확보 실패·미평가는 재개 대상으로 남긴다. 예산 종료·조회 실패·평가 실패는 결과 상태·안내에 표시한다.

## 저장과 후속 사용

평가·읽은 구간·내용 확보 기록·평가 입력 해시·보류 사유는 `evidence_feed`, 계획·실행 검색어·대기 검색어·회차별 수치·미확인 항목·종료 사유는 `synthesis_report.discoveryContext`에 저장한다. `POST /research/sessions/{id}/continue`는 expectedUpdatedAt을 받아 같은 세션의 미완료 작업을 재개한다. 입력 해시가 같은 평가는 재사용하고 새 구간이 생기면 현재 평가 완료 전까지 후속 사용을 막는다. AI 질문 해석 실패 세션은 재개 시 계획을 다시 요청한다. 재개·종합 분석은 저장 버전 비교와 임시 실행 기한으로 중복 실행을 거절한다(409). 종합 분석은 기존 `comparisonContext`와 `discoveryContext`를 보존하며, 근거 서명이 바뀐 보고서는 재생성 전 내보내기를 막는다. 테이블 추가·과거 세션 일괄 변환·백그라운드 작업 큐는 없다.

새 결과는 확보 내용과 included 판정이 모두 있어야 종합 분석·비교 보강·티켓 내보내기에 사용할 수 있다. 과거 세션은 기존 확보 상태 검증과 명시적 선택을 유지하며 평가 기록이 없다고 표시한다. 평가 설명은 문헌 사실로 재인용하지 않는다. 위키 반영은 기존 검토·승인 경로를 따른다.

## 검증

`verify_research_flow.py`는 기존 문헌→종합 분석→티켓→검토와 비교 왕복의 회귀를 메모리 DB에서 확인한다. `verify_research_discovery.py`는 HBM 질문 해석, 근거 설명, 보류·제외, 구간 ID 검증, 보완 검색, DOI 통합, 긴 등록 발췌 보존, 과거 세션, 맥락 보존과 실패 상태를 확인한다. 새 검사는 DB를 메모리로 강제하고 모델·검색 외부 응답을 명시적으로 모의한다.

`verify_research_continuation.py`는30건 초과 보존·동일 세션 재개·변경 없는 평가 재사용·버전/동시 실행409·AI 장애 회복·조회 실패 재시도 저장·HTML/PDF 귀속·위험 링크/사설DNS 거절을 확인한다. 실제 외부 자료의 접근성과 AI 응답은 별도의 메모리 DB 서버에서 검증한다.

브라우저 검증 서버는 `python scripts/verify_research_discovery.py --serve`이며 전용 루프백 포트 18004와 메모리 DB를 사용한다. 프론트 프록시는 별도 격리 설정에서 이 포트를 지정한다. fixture의 문헌과 설명은 테스트 데이터이며 실제 연구 결과가 아니다. 실제 모델 응답 품질과 Crossref 접속 검증은 모의 검사와 구분해 보고한다.
