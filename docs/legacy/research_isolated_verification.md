# 문헌 조사 실제 AI 격리 검증

## 실행과 보존 경계

`Settings`의 기본 `.env`는 현재 실행 폴더 기준이다. 다른 체크아웃에서 실행하면 기존 제품 설정을 자동으로 찾지 않는다. 서버 설정도 요청의 `X-OpenAI-Key`도 없으면 Gateway는 네트워크 호출 없이 `None`을 반환한다. `source_only` 화면만으로 API 장애나 모델 오류를 판단하지 않는다.

기존 가상환경에서 `python scripts/run_isolated_research.py --env-file <기존 .env 절대 경로>`를 실행한다. 별도 포트의 프론트엔드 프록시는 `http://127.0.0.1:18004`를 사용한다. 이 실행 도구는 지정한 설정을 프로세스에서만 읽고, 앱 import 전에 SQLite 메모리 DB와 인메모리 캐시를 강제한다. 서버는 loopback으로만 연다. 설정 파일이나 인증값을 체크아웃으로 복사하지 않고 인증값을 출력하지 않는다. 설정에 OpenAI 인증이 없으면 서버를 열지 않고 종료한다.

실행 도구는 기존 API → Service → ResearchDiscoveryAgent → Gateway와 Repository 호출을 그대로 사용한다. 제품 Gateway, 모델 선택, DB 설정 계약은 변경하지 않는다. 앱 시작의 테이블·계정 생성과 조사 이력 저장은 메모리 DB에만 반영된다. 프로세스 종료 시 검증 이력은 사라진다. 운영 DB나 운영 서버의 API를 프록시 대상으로 지정하지 않는다.

## 실제 AI 확인

상세 평가는 최대4문헌·합계12000자·40초로 나누고 기존 전체 조사 예산150초 중 남은 시간 안에서 실행한다. HTTP 단계별 제한과 별도로 `asyncio.wait_for`가 평가 전체를 제한하며, 초과 시 평가를 취소하고 미완료 작업을 같은 세션에 저장한다. 경량 모델로 조용히 대체하지 않는다.

각 검색의 외부 문헌 후보를 파일 원문보다 먼저 후보 풀에 넣는다. 검색당30개와 화면 첫30개는 전체 세션의 저장 한도가 아니다. '이어서 조사하기'는 같은 세션의 남은 검색·확보·평가를 실행한다. 기존 DB 등록 발췌와 같은 DOI의 ID·원문 보존 우선순위는 유지한다. 관련성 판단은 Agent가 읽은 구간으로 결정한다.

Agent는 검색 계획과 후속 검색어를 Crossref `query.bibliographic`의 자유 텍스트에 맞게 작성한다. 이 도구는 Boolean 구문을 지원하지 않으므로 `OR`·괄호로 동의어를 나열하지 않고 별도 검색어로 나눈다. 근거: [Crossref 공식 안내](https://community.crossref.org/t/advanced-set-boolean-operators/4596).

외부 API 전송이 허용된 질문과 자료만 사용한다. 이 경로는 기존 OpenAI API로 질문·검색 계획·확보한 문헌 구간을 전송하고, Crossref API로 검색어를 보낸다. 비공개 원문은 별도 전송 허용 없이 포함하지 않는다. 고정 응답 검증은 실제 AI 품질 검증과 구분한다.

`HBM 하이브리드 본딩에서 수율을 떨어뜨리는 요인`을 입력해 실제 질문 해석, 실행 검색어, 확보 범위, 포함·보류·제외 사유, 판단에 사용한 근거 구간을 확인한다. 초록 없는 서지정보는 보류하고, 초록·일부 발췌를 전문 검토로 표시하지 않는지 확인한다. AI HTTP 성공뿐 아니라 응답 DTO 검증과 화면 표시까지 성공해야 실제 흐름 통과로 기록한다. 검증 후 서버와 임시 브라우저 탭을 종료한다.

## 2026-10-23 추가 검증 결과

운영 설정을 메모리에서만 읽고 별도 체크아웃·루프백18004/13004·메모리 DB/캐시에서 OpenAI gpt-6.1-sol medium과 Crossref를 실제 호출했다. 기존 사용자 변경은 보존한 working 상태에서 검증했다. 이 커밋만의 깨끗한 체크아웃 실행은 검증하지 않았다.

HBM 질문의 화면 입력→질문 해석→탐색→관련성 설명→같은 세션 재개를 확인했다. 첫 실행은61후보·평가 처리12건 중 현재 유효한 평가11건(포함1, 의미상 보류5, 제외5)이었다. 화면에서 재개한 뒤85후보·현재평가22건(포함1, 의미상 보류7, 제외14)으로 저장됐다. 기존61개 ID와 선택한 YAP+ 문헌을 유지했다. 나머지는 내용 미확보35·평가 대기24·평가 실패4건이다. 첫 화면의 유효한 평가11건 중 새 읽기 구간이 생긴2건은 다시 평가했고 나머지9건은 같은 평가를 재사용했다. 상태 필터·판단 근거 표시·재개 중 선택/분석 차단을 화면에서 확인했다.

자동 공개 원문 확보는13주소 시도 중 성공0건이었다. IEEE는202 접근 확인 응답, 다른 출판사 페이지도 문헌 귀속이 확인되지 않아 읽은 원문으로 저장하지 않았다. 성공한 탐색7회와 미완료 작업은 보존했다. 검색 확대만으로 포함 문헌이나 공개 원문 확보가 늘었다고 보고하지 않는다.

별도로 검색 후보인 `Deep Convolution Neural Networks for Automatic Detection of Defects which Impact Hybrid Bonding Yield`의 저자 공개 PDF 주소를 제공해 실제 HTTP→PDF 추출→6000자 읽기 구간→동일 AI의 included 판단·한국어 설명·실제 구간 ID 참조를 확인했다. 이는 자동 URL 발견 성공에 포함하지 않았다. AI는 표면 결함 검사 연구를 일반 공정 보조 근거로 설명하고 HBM 실제품 수율 검증과 구분했다. 이 결과는 자동 경로의 원문 발견·접근이 남은 병목임을 보여주며 문헌 부족을 확정하지 않는다.

모의 외부 응답과 메모리 DB를 사용한 discovery·continuation 회귀 및 프론트 빌드는 통과했다. continuation 검사는30건 초과 보존, 변경 없는 평가 재사용,409 충돌, 일시 AI 장애 회복, 실패 검색 재개, HTML/PDF 귀속, 위험 링크·사설DNS 차단과 외부/긴 등록 출처의 비교 보강→티켓 저장을 확인했다. 기존 `verify_research_flow.py`는 이전 무평가 fixture 계약 때문에 단독 실행이422였으며, 파일을 수정하지 않고 새 계획·평가 계약의 명시적 모의 어댑터를 적용한 실행은 통과했다.

공개 HTML/PDF는 문헌 일부만 읽으며 OCR·일반 웹 검색·저자 저장소의 자동 발견은 지원하지 않는다. 모델 설명 일부가 한국어 지시에도 다른 언어로 반환됐고, 의미가 비슷한 후속 검색어가 반복 제안되는 품질 한계도 관찰했다. 전체 조사 완료, 모든 관련 문헌의 발견, 유료·접근 제한 원문 확보, HBM 양산 수율의 정량 검증을 주장하지 않는다. 운영 데이터 수정·위키 적용·원격 push·배포는 수행하지 않았다.
