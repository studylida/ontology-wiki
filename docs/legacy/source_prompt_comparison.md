# 원문 추출 프롬프트 비교 — 2026-10-22

## 결정

공통 프롬프트와 근거 검증을 보완했지만 **판단 예시의 전체 품질 개선은 확인하지 못했다. `use_examples=False`를 기본값으로 유지하고 129건 일괄 추출·적용은 하지 않는다.** 예시는 일부 판단에 도움이 됐으나 정상 지식 누락과 더미 설명 저장도 발생했다. API 성공을 내용 품질 통과로 계산하지 않는다.

이번 변경은 기존 `SourceExtractionService` 안의 원문 정제·프롬프트·검토만 보완한다. API, SSE, DTO, Repository, Entity, 프론트엔드 계약과 운영 DB를 바꾸지 않는다. 정상 본문·전문가 수정·다른 출처 기여를 보존하는 기존 병합·적용 경로를 사용한다. 기존 DB의 잘못된 내용을 수동으로 고치거나 이미 적용된 사례를 일괄 재평가하지 않았다.

## 비교 방법

- A: 예시 없는 공통 프롬프트. B: 같은 코드·모델·출력 계약에 판단 예시만 선택적으로 추가한다. 기본 서비스 인스턴스에서는 B를 켜지 않는다.
- 이전에 살펴본 129건 중 예시 원문 8건 및 앞선 실험 10건과 겹치지 않는 4건을 사전에 골라 19개 사실 점검 기준을 고정했다. 이미 실패를 분석한 3건은 별도 회귀 자료로 사용했다. 이 4건도 전체 자료를 처음 읽는 의미의 미열람 문서는 아니며, 이 실험 후 새로운 검증 세트로 재사용하면 안 된다.
- Tier 1은 `gpt-4o-mini`, Tier 2는 `gpt-4o`이다. 모델 호출의 난수·서버 버전을 고정하지 않았으며 각 최종 조건은 1회다. 소요 시간 차이를 통계적 성능 개선으로 해석하지 않는다.
- 문서·조건마다 별도 프로세스와 빈 SQLite 메모리 DB를 사용했다. 모델에는 공개 원문과 그 원문에서 만든 후보만 보냈다. 운영 DB·기존 위키 카탈로그는 조회하거나 모델에 전달하지 않았다.
- 실제 관리자 API의 문서 목록 → 추출 SSE → 미리보기 → 적용 → 개념 상세 조회를 ASGI로 실행했다. 브라우저를 통한 클릭 검증은 이번 범위에서 하지 않았다.
- 전체 문자 구간 처리 여부와 최종 위키에 필요한 지식이 남았는지는 별도로 확인했다. `sourceCoverage.complete`는 의미적 누락이 없다는 보증이 아니다.
- 최종 비교 전 두 후보를 폐기했다. 첫 후보는 독립 코드 리뷰의 메뉴 제목·빈 관계 ID·수평선 처리 지적으로, 두 번째는 알려진 회귀 자료에서 발견한 명칭 정정 재시도·관계 단건 보류 문제로 수정했다. 예시와 사실 점검 기준은 바꾸지 않았고, 이전 후보의 결과를 최종 수치와 섞지 않았다.

## 코드에서 보완한 경로

- `clean_web_noise()`가 YAML 메타데이터, 삼성 메뉴와 본문 경계, 식별 가능한 웹 UI·연결된 푸터를 제외한다. 일반 기술 문장에 UI 단어가 있다는 이유로 지우지 않으며, 관련 글 이후의 기술 문장을 일괄 자르지 않는다. 실제 `반도Chat`·`MWC 2014` 제목도 본문으로 인식한다.
- `validate_quotes()`가 같은 정제 원문을 사용한다. 숫자의 영문·숫자 경계와 `돌파/상회/가량/정도` 등 한정어를 검증한다. 과거 푸터 인용을 미리보기·적용에서 다시 사양으로 인정하지 않는다. 기존 모든 위키 내용을 소급 정리하는 기능은 아니다.
- `build_publisher_prompt()`는 발행사별 강제 기술·수치 설명을 제거하고 공통 위키 계약을 따른다. 플레이북의 과거 독립 스키마를 실제 DTO 매핑과 원문 조건부 참고 기준으로 정리했다.
- `review_relation_subjects()`를 기존 전후·대안에서 `isA`, `partOf`까지 확장했다. 원문에 명칭이 있는 미등록 대상도 정상 ID로 참조할 수 있으나 빈 ID는 허용하지 않는다. 응답 계약 누락은 실패, 정정 후에도 확인되지 않는 단일 관계는 경고와 함께 보류한다.
- `review_perspective_cases()`는 구간별 파라미터 보완 후 현재 원문에서 얻은 신규 사례만 검토한다. 회사·제품·상황과 각 수치·단위·마진의 귀속을 확인하며 틀린 사양만 제거할 때 맞는 사례 설명을 유지한다. 검토 계약 오류가 있으면 중간 배열을 저장하지 않는다. 의미 판정은 여전히 모델에 의존하며 정상 사례 과잉 보류가 남아 있다.
- `judgment_examples()`는 기본 비활성이다. 격리 비교의 명시적 `use_examples=True`에서만 단계·입력에 맞는 원문 기반 예시를 최대 2개, 6,000자 내로 선택한다. 예시 JSON의 출처 SHA·발췌를 검사하며 현재 문서의 근거로 사용할 수 없다고 구분한다. 새 관리자 설정이나 UI는 만들지 않았다.

## 검증과 재현 정보

## 다음 확대 조건

현재 변경을 완전 자동 편입의 품질 보증으로 사용하지 않는다. 관리자 미리보기를 유지한다. 정상 사례의 과잉 보류, 보호 토큰·단위·한정어의 정량 복원 손실, 서로 다른 개념의 구간 간 혼입과 누락을 먼저 줄인 뒤 예시 원문과 겹치지 않는 새 문서로 다시 평가해야 한다. 이 결함을 특정 문서 정답·DB 수정·화면 숨김으로 보정하지 않는다. 이 조건이 확인될 때만 예시 활성화와 129건 확대를 진행한다.
