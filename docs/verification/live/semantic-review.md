# 실제 생성 사례의 근거·의미 검토 — 2026-10-26

## 1. 검토 결론과 범위

초기 위키 답변, 후속 비교 답변, 근거가 부족한 질문의 Basic/Extended 답변, 개인 위키 v2를 당시 사용한 문헌 3건과 대조했다. **이 사례들의 답변 본문에서는 원문에 없는 접합 온도·압력·허용 휨·양사 수율 수치를 만들어 낸 부분을 발견하지 않았다.** 문헌이 다루는 범위를 구분하고, 자료에 없는 내용과 추가로 필요한 근거를 설명했다. 개인 위키 v2도 비교의 핵심 제한을 유지했다.

반면 초기 관계 카드의 조건 없는 `alternative_to`, Extended v1의 검색 충족 표시, 개인 위키의 일부 내용 압축, 후속 추출의 발언자·성능 조건 생략은 구분해서 기록해야 한다. 답변이 자연스럽고 인용 ID가 연결된다는 사실만으로 의미 검증을 마쳤다고 판단하지 않는다.

이 문서는 **개발 중 얻은 소수 실제 호출 결과를 다른 AI 작업자가 원문과 읽어 대조한 사례 검토**다. 반도체 전문가의 정답 작성·승인, 사람 평가, 모델 결과를 보지 않고 설계한 홀드아웃 평가, 전체 문헌의 검색 재현율 평가가 아니다. 검토자가 새 모델 호출, 외부 웹 조회, 운영 데이터 변경을 수행하지 않았다. 이 검토를 바탕으로 전체 서비스의 정확도 점수나 모델 간 우열을 산출하지 않는다.

검토 중 생긴 후속 산출물 `gap-extended-fixed.json`, `ontology-fixed.json`, 수정 후 `research-roundtrip.json`은 **8절의 별도 후속 확인**으로 다룬다. 초기 파일의 결함을 없었던 것으로 바꾸지 않는다.

## 4. 조건·수치·문헌 귀속 검토

### 유지된 사항

- 초기 위키·비교 답변은 **적층 높이 증가에 따른 휨**과 **밀집 구조의 발열**을 구분했다. 허용치나 성능 개선율은 만들지 않았다.
- Basic/Extended 질문에 대해 자료에 없는 온도·압력·수율 값을 채워 넣지 않았다. “자료에 없음”을 기업 내부 규격이나 다른 공개 문헌의 부재로 단정하지 않았다.
- S1의 HBM 소개와 S2의 TSV 설명을 구분했고, S3의 일반 패키징 교육을 양사의 동등 조건 HBM 공정 데이터로 간주하지 않았다.
- 원문에 있는 정성적 성능 설명은 원문에 귀속했다. 뉴스룸 설명을 기업 전체의 공식 입장이나 실제 제품 사양으로 일반화하지 않는 문구도 포함했다.

### 남는 정밀도 한계

**조건을 하나의 인과로 합친 표현:** `gap-extended.json`은 적층 수가 늘수록 휨과 발열 문제가 커진다고 묶어 설명한다. 후속 `gap-extended-fixed.json`에도 “적층 높이가 늘면 휨 현상과 발열 문제가 심화”라는 표현이 있다. S2의 해당 구간은 높이 증가와 휨, 밀집 구조와 발열을 각각 설명한다. 앞선 위키·비교 답변과 개인 위키는 이 구분을 유지했으므로, 후자의 문장은 그보다 조건 표현이 거칠다. **새 수치를 만든 환각은 아니지만, 원문보다 인과 범위를 넓힌 경미한 의미 압축**으로 기록한다.

**정량 근거의 종류 구별:** S1에는 교수의 소개 발언으로 범용 D램보다 데이터 전송량을 “수백 배” 늘린다는 표현이 있다. 따라서 세 원문 전체에 어떤 수량 표현도 없다고 말하면 부정확하다. 그러나 이것은 질문한 TSV의 개선율, 접합 조건, 세대·측정 조건이 명시된 성능 사양이나 양사 수율 비교가 아니다. 검토한 네 답변은 이 표현을 질문에 없는 숫자 답변으로 전환하지 않았다.

**귀속·시점 메타데이터:** 인용은 게시 매체를 보존하지만 작성자/발언자/게시일은 충분히 복원되지 않았다. 특히 S3의 본문에는 2018년 게시일이 있는데 citation/source-view의 날짜는 null이다. 이 자료를 최신 제품 조건이나 시기별 기업 견해 비교에 바로 쓰기에는 한계가 있다. 본문에 있는 날짜의 누락과 모델이 날짜를 지어낸 오류는 구분한다.

## 5. 위키·분석 형식과 관계 카드

초기 위키는 `핵심 설명 → 목적·원리 → 사례·조건 → 관계 → 출처·부족한 부분`의 다섯 부분 순서를 지켰다. 분석 답변은 비교표, 문헌별 적용 범위, 대체 가능성 판단으로 질문에 맞는 형식을 사용했다. 두 응답은 같은 대화에 남았으며 자료 범위도 유지했다. 다만 API 기록을 읽은 이번 검토만으로 토글 클릭·관계 펼침의 무호출 동작이나 화면의 가독성을 새로 검증했다고 말하지 않는다.

위키 본문의 `관계` 부분은 대부분 게시자별 문헌 범위 비교다. 상위 분류와 선행/후속 관계는 별도 `relations` 배열에 전달됐다. 따라서 다섯 제목이 맞다는 이유로 관계 설명의 정보 구조까지 완성됐다고 판단하지 않는다. 본문과 카드가 함께 읽힐 때 의미가 연결되는지는 별도 화면 검토 대상이다.

초기 네 답변에는 같은 TSV–와이어 본딩 관계 `rel_2937d7e13c6747c7a2d40ac8c50235cf`가 들어 있다.

- `type=alternative_to`, `conditions=null`, `status=machine_extracted`.
- 근거는 S2의 두 연결 경로를 대비한 구간이다. 설명문은 대조라는 점을 적었지만, **대안 관계 라벨만 읽으면 모든 패키지에서 교체 가능한 관계로 받아들일 수 있다.**
- 비교 답변 본문은 보편적 대체 가능성을 명확히 부정했다. 즉, 본문이 신중하다는 사실만으로 부속 카드의 관계 의미까지 안전해지는 것은 아니다.
- `machine_extracted` 상태와 문헌 근거가 있다고 해서 관계의 설계 적용 조건이 검증된 것은 아니다. 문헌 승인 이후 별도 주장 승인 절차를 도입하자는 결론도 아니다. 자동 추출의 조건·표현·근거 처리가 개선돼야 할 사례다.

초기 `is_a` 관계의 조건이 null인 것 자체를 모두 오류로 분류하지 않는다. TSV가 패키지 기술로 소개된다는 분류와, 한 연결 기술이 다른 기술을 대체할 수 있다는 적용 판단에는 요구되는 조건의 강도가 다르다.

## 6. Extended 초기 결과의 해석

초기 Basic은 `stopReason=basic_search_completed`였고, Extended v1은 `coverage_target_reached`였다. 그러나 Extended의 요구 항목은 목적·일반 조건·비교의 넓은 범주뿐이며, 실제 질문의 온도·압력·허용 휨·수율 값이 충족됐는지 구분하지 못했다. `extraQueries=0`, `semanticSufficiency=not_evaluated`, 각 판정의 `assessment=literal_aspect_signal_only`가 기록돼 있다.

또한 조건 후보에는 S3 YAML 메타데이터 구간까지 포함됐다. 이 상태를 사용자에게 질문의 근거가 충분히 확보됐다는 뜻으로 해석시키면 잘못이다. **답변 모델은 근거 부족을 적절하게 설명했지만, 검색 단계의 종료 이유가 그 의미를 과장한 사례**다. 이는 답변 생성의 수치 환각과 다른, 탐색 계획·충족 상태의 문제다.

이 한 쌍에서는 Extended가 정량 근거를 더 확보하거나 답변 품질을 높였다고 주장할 수 없다. 추가 쿼리를 실행하지 않았고, 문헌 hit 수 차이 자체도 의미적 충족을 증명하지 않는다. 수정 후 상태는 8절에 별도로 기록했다.

## 7. 개인 위키 v2의 보존과 누락

v2 제목은 **TSV·와이어 본딩·플립칩: 연결 경로와 적용 범위**다. 다음 내용은 보존됐다.

- 삼성 자료의 칩–기판 연결과 SK 자료의 적층 칩 연결을 구분한 비교표.
- TSV의 수직 연결, 와이어 우회 경로, 플립칩 범프 연결의 근거.
- 휨과 발열의 조건 구분, 소재·공법·수율·신뢰성 과제.
- 정량 성능·허용 적층 수·구체 공정 한계가 없다는 제한.
- 모든 패키지의 대체 가능성·기술 간 성능 순위를 추론할 수 없다는 제한.
- 뉴스룸 문헌을 기업 전체의 공식 입장으로 일반화하지 않는 제한.
- 두 원메시지의 연결과 원문 구간 3개. AI 요약이나 개인 위키 자체를 독립된 출처로 인용하지 않았다.

현재 v2에서는 첫 위키 답변에 있던 다음 정보가 줄거나 없어졌다.

| 첫 답변의 내용 | v2의 상태 | 해석 |

| HBM을 수직으로 쌓은 D램으로 설명 | HBM 적층 맥락은 남지만 D램 정의가 명시적으로 남지 않음 | 비교 주제 중심으로 압축한 결과다. HBM 정의를 이 페이지 하나만으로 복습하려면 정보가 줄었다. |

이 누락은 현재 v2의 비교 결론을 거짓으로 만들지는 않는다. 그러나 두 메시지를 합친 개인 위키가 앞선 설명의 모든 유용한 사실을 보존한다는 보장도 없다. 판본 메타데이터와 원메시지가 남는 점은 추적에 도움이 되지만, 이번 파일만으로 v1 본문 복원까지 검증하지 않았다. `evidenceStatus=source_linked`, `warnings=[]`는 출처 연결 상태이며 전문가 의미 승인을 뜻하지 않는다.

## 8. 검토 중 도착한 수정 후 실제 결과

### 8.1 Extended v2 — 같은 부족 근거 질문

[gap-extended-fixed.json](gap-extended-fixed.json), 05:10:51 UTC, `run_946c5b388b994792aabc96c490c0196a`를 별도로 읽었다.

- `planner=bounded_parameter_aspect_rules_v2`.
- 온도·압력은 `unknown`, 휨·수율은 관련 원문을 찾은 `candidate_found`로 표시한다. 후보가 있다는 사실을 수치가 확인됐다는 뜻으로 바꾸지 않았다.
- 내부 추가 검색 1회 뒤 `stopReason=no_new_evidence`로 종료했다. `semanticSufficiency=not_evaluated`는 그대로 남았다.
- 답변은 정확한 공정 수치와 양사 수율을 모른다고 설명하며, 자료의 부재가 기업 내부 기준의 부재를 뜻하지 않는다고 명시했다.

초기 상태의 **의미를 과장한 충족 표시는 이 후속 사례에서 개선**됐다. 다만 일반 조건 후보에 메타데이터 구간이 남아 있어 후보 선정의 정밀도까지 완성됐다고 할 수 없다. 추가 검색 1회가 모든 예산 경계·취소·불필요 반복을 검증하지도 않는다. 4절의 높이/발열 조건 압축도 남았다.

### 8.2 관계·개념 재추출

[ontology-fixed.json](ontology-fixed.json)은 05:12:49~05:13:42 UTC에 별도 새 개발 스키마에서 수행한 실제 추출이다. 원문 3건, 정책 `source-extract-v2-canonical-identity`, 개념 13개·출처별 설명 15개·관계 9개가 기록됐다.

- `duplicateLabels=[]`, `alternativeRelationsWithoutConditions=[]`이다. HBM과 와이어 본딩이 문헌별 설명을 여러 개 가지면서 동일 개념 ID를 사용하는 것도 결과에서 확인했다. 이는 이번 중복 사례에 대한 확인이며, 모든 별칭·동음이의어 해소의 정확성 보장은 아니다.
- 초기의 조건 없는 TSV–와이어 본딩 `alternative_to`는 이 결과에 없다. 와이어 본딩–플립칩의 대안 관계는 **칩과 기판을 연결하는 선택지**라는 조건을 포함한다. 와이어 본딩→성형 순서도 해당 와이어 본딩 경로라는 조건을 포함한다.
- 문헌의 실제 단계·분류와 관계 근거를 대조했으며, 이 표본에서 단계의 순서를 뒤집거나 TSV 제조 레시피를 새로 만든 관계는 발견하지 않았다.
- **발언 귀속의 남은 한계:** HBM 설명에 S1의 “수백 배”가 재사용됐다. 수치 표현은 원문에 있어 새로 만든 숫자는 아니다. 그러나 원문은 신창환 교수의 소개 발언이며 제품 세대·비교 기준·측정 조건이 없다. 설명에는 발언자가 생략되고 `attributedTo=null`이므로, 이를 SK 전체의 검증된 현행 성능 규격으로 받아들이면 안 된다. 게시자와 발언자가 다른 경우 요약에서도 발언 맥락을 보존해야 한다.

이 파일은 `retrievalValidated=false`, `publicDataWrites=false`다. 새 추출 결과를 사용한 공통 RAG 검색·카드·새 대화 응답 전체가 여기서 검증된 것은 아니며, 초기 답변의 저장된 관계가 자동으로 바뀌었다는 증거도 아니다. 파일의 `semanticValidation=not_human_reviewed`는 이 AI 읽기 검토 후에도 타당하다.

### 8.3 외부 문헌 설명의 문자열 분해 오류

앞선 실제 fetch에서 모델이 `limitations`를 단일 문자열로 반환했을 때, 기존 처리가 문자열을 글자 단위로 잘라 저장한 결함이 있었다. 이는 원문 의미를 해석한 차이가 아니라 응답 계약 처리 오류다. 문자열 한 문장을 한 항목으로 정규화하고, 잘못된 형태는 설명 생성 실패로 처리하도록 수정했으며 관련 회귀 테스트가 별도로 있다.

검토한 최신 [research-roundtrip.json](research-roundtrip.json), 05:11:05 UTC의 실제 fetch는 `relevanceStatus=generated`이고, `limitations`가 완전한 문장 5개로 저장됐다. `readScope=partial`, HTML 추출의 제한, 문서 전체를 읽지 않았다는 설명, 기업 제품 사양으로 확대할 수 없다는 제한도 남았다. **단일 문자로 분해되던 오류의 재발은 이 후속 기록에서 보이지 않는다.**

이 검토의 원문 3건에는 Lam Research 웹 문서가 포함되지 않는다. 따라서 이 절에서는 수정 후 형식·범위 표시를 확인한 것이며, Lam 문헌 요약의 모든 사실을 독립적으로 대조했다고 주장하지 않는다. 앞선 잘못된 저장 레코드가 모두 소급 교정됐다고도 주장하지 않는다.

## 9. 이 결과로 말할 수 있는 것과 후속 확인

이번 사례는 실제 모델 응답이 문헌 범위를 구분하고, 정량 근거 부족을 설명하며, 비교 결과를 개인 위키로 정리하는 흐름을 보여 준다. 동시에 **검색 충족 상태, 관계 카드, 출처별 설명, 누적 요약은 답변 본문과 따로 평가해야 한다**는 결함도 드러냈다.

후속 품질 검토에서 우선 확인할 내용은 다음과 같다.

1. 새 관계 추출을 실제 공통 RAG·카드·대화 경로에 연결했을 때, 조건 없는 대안 관계와 잘못된 개념 합치기가 다시 생기지 않는지 확인한다.
2. 수치가 실제로 있는 문헌을 넣어 단위·조건·발언자·제품 세대를 함께 보존하는지 확인한다. “없는 숫자를 만들지 않는다”만으로 수치 답변 능력을 평가하지 않는다.
3. 조건을 병렬로 설명한 원문을 하나의 인과로 합치지 않는지 확인한다. 이번 높이–휨/밀집–발열 사례를 회귀 예제로 사용할 수 있다.
4. 개인 위키 여러 차례 병합에서 정의·조건·한계·문헌별 차이가 얼마나 남는지, 이전 판본·원메시지에서 실제로 복원할 수 있는지 확인한다. 비교 중심 압축과 원치 않는 정보 손실을 구분한다.
5. 전문가가 독립적으로 정의한 질문·근거·허용 추론 범위로 더 넓은 자료와 실패 사례를 평가한다. 본 기록을 그 정답집이나 홀드아웃 결과로 재명명하지 않는다.
