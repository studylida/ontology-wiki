# 탭2의 대상 확인과 목적별 비교

기존 comparison API → ComparisonService → ClarifierAgent로 질문 해석을 위임한다. Service는 기존 Repository에서 등록 이름·영문명·별칭·ID를 조회하고 Agent는 질문을 A/B·목적·적용 맥락·평가 축의 초안으로 분석한다. 위키 목록은 연결 참고자료이며 입력 어휘 제한이 아니다. 미등록 표현도 초안에 보존하며 TC-NCF를 열압착 본딩으로 자동 치환하지 않는다. 테이블·마이그레이션·새 Service는 추가하지 않는다.

구체화 요청의 query는 원래 질문, draft는 수정 가능한 targetAName·targetBName·purpose·applicationContext·axes, answers는 확인 답변이다. 선택적 targetA/targetB는 이와 별도의 확정 등록 ID다. 응답도 draft를 반환하고 기존 branches·dynamicAxesPool·clarificationQuestions 계약을 유지한다. Service는 모델이 만든 ID를 채택하지 않고 등록명 일치와 사용자가 확인한 연결만 사용한다. 미등록 초안도 ready가 될 수 있으며 확인 질문은 부족한 내용에만 사용한다. 위키 근거 비교 실행에는 기존대로 두 등록 ID가 필요하고 미연결 초안은 기존 문헌 조사로 넘길 수 있다. 비교 생성 후에는 contextParams.draft에 질문 해석과 사용자 수정을 보존한다.

Agent는 기존 Gateway의 tier1_fast를 사용해 구조화 초안을 생성·검증하며 고정 기술·분기·축과 도메인 단어 목록 차단을 제거한다. Service의 자연어 정규식 해석과 별도 모델 우회 경로는 제거했다. 공용 Agent의 챗봇 메서드는 변경하지 않는다. AI 무응답·예외·형식 오류에는 원래 질문과 작성한 초안을 유지하고 상태를 표시하며 성공한 분석으로 가장하지 않는다. 사용자가 입력한 값과 선택한 축은 재분석으로 덮지 않는다. 질문 또는 초안 수정은 진행 중 응답을 무효화한다.

선택한 평가 항목은 기존 contextParams.axes에 label·검색어와 함께 저장한다. 질문에 명시한 항목, 모델이 제안한 항목, 사용자가 직접 입력한 항목을 구분해 확인할 수 있다. 모델은 항목과 검색어를 제안하며 셀의 수치·성능·우열을 만들지 않는다. 목적별 셀은 관련 등록 위키 설명과 기존 knowledge() 검증을 통과한 공개 사양의 발췌만 사용한다. 근거가 없으면 '공개 근거 미확인'으로 표시하며 전체 문헌에 없다고 판정하지 않는다. 기존 위키 배경과 출처별 사양은 별도 필터로 열람한다.

기존 공개 여부, 복수 근거, 수치 부호·Unicode 부호·단위·조건 검증은 그대로 유지한다. 조사에서 연결한 미검토 문헌은 해설 자료이며 위키 사양으로 자동 승격하지 않는다. 조사 왕복은 원래 세션의 대상·질문·평가 항목·이력을 유지한다. 검토 출처 패치와 승인 트랜잭션은 변경하지 않는다.

기존 SetupTrackSelector에서 Agent 추천 초안을 편집하고 같은 값을 Track2 직접 지정에 적용한다. 위키 연결 검색은 초안 이름과 별도로 표시하고 미등록 초안의 대상·목적·맥락·축을 지우지 않는다. 기존 Controller는 문헌 조사로 이동할 때 비교 세션이 없는 초안의 검색 주제를 만들며 존재하지 않는 비교 ID를 합성하지 않는다. 대상 선택 View의 등록명·영문명·ID·별칭 검색과 키보드 선택, 기존 안전한 Markdown·출처 이동을 유지한다.

격리 검증은 실제 등록 지식 테이블만 읽어 메모리 DB에 옮기며 계정·비교/조사 세션·티켓·감사 기록을 운영 DB에서 복사하지 않는다. scripts/verify_comparison_flow.py는 모의 AI로 대상 확인·목적별 항목·출처 보존·권한 및 기존 사양 검사를 실행한다. scripts/verify_comparison_frontend.mjs는 입력 상태·지연 응답·검색·Markdown 보안을 검사한다. 운영 DB 변경·운영 티켓 승인·제품 서버 재시작·push·배포는 검증 범위에 포함하지 않는다.
