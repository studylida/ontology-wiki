# 설계 결정과 구현 가정

## ADR-01: 대화 중심의 모듈형 단일 서비스

새 사용자 작업을 기준으로 UI·도메인을 재작성했습니다. 기존 네 개 탭별 Controller·DTO·Service·테이블을 보존하는 호환 계층은 만들지 않았습니다. React/TypeScript/Vite와 FastAPI/Pydantic/SQLAlchemy는 복잡한 상호작용·명시적 계약·Python 문서 처리에 적합해서 선택했습니다. Next.js의 SSR이나 별도 서비스 분리는 현재 내부 업무형 사용 사례에서 필수 이점을 확인하지 못해 도입하지 않았습니다.

## ADR-02: PostgreSQL + pgvector

사용자가 확정한 저장소입니다. 판본·권한·승인·관계·벡터를 한 트랜잭션 경계 안에서 다룰 수 있습니다. 그래프 DB를 추가하지 않고 타입/방향/조건과 여러 근거가 있는 관계 행을 저장합니다. 현재 필요한 탐색 깊이에 비해 별도 그래프 운영·동기화 비용을 추가할 이유가 없습니다.

정확 코사인 검색 + 명시적인 문자열 검색을 결합합니다. 한국어 형태소 처리 없는 SQL 문자열 검색을 한국어 BM25라고 부르지 않습니다. ANN은 검증 corpus에서 필수가 아니며, 향후 규모에서 지연/recall을 측정한 뒤 추가합니다.

## ADR-03: 개인 지식과 공용 근거 분리

사용자 대화의 정리는 개인 위키로만 축적합니다. 잘 정리된 AI 답변이라는 이유로 공용 사실·원문으로 승격하지 않습니다. 공용 자료 축적은 선택한 공개 문헌의 검토를 통해 이루어집니다. 개인 위키 정리는 페이지와 판본, 원메시지, 조건, 실제 근거를 가지며 중복·삭제·사용자 수정 충돌을 제어합니다.

**초기 가정:** 개인 위키 자동 정리 기본 켜짐. 사용자 전체 설정과 대화별 제외로 변경할 수 있습니다. 삭제/되돌리기/제외 기록은 정책 버전이 바뀌어도 유지합니다. 과거 답변 전체를 자동 재정리하지 않습니다.

## ADR-04: 출처별 관점은 귀속된 설명

기업 도메인이나 문헌 폴더명만으로 “그 회사의 공식 입장”을 만들지 않습니다. publisher, author, attributedTo, attributionBasis, sourceType, 날짜, aspect, conditions를 분리합니다. source view는 승인 원문에서 파생된 설명이며 독립 증거 수를 늘리지 않습니다.

기존 “SK” 표현은 우선 SK하이닉스로 이해하는 가정이지만 실제 데이터는 확인된 발행자 이름/ID를 사용합니다. 커뮤니티 문헌이 없으면 없다고 표시합니다. 서로 다른 측정 조건·제품 세대의 숫자를 같은 조건의 비교로 만들지 않습니다.

귀속 메타데이터 정정 시 이미 생성한 요약 안의 잘못된 귀속도 무효화합니다. 원문 임베딩 입력이 같으면 재임베딩하지 않아도 됩니다. source view 재추출은 별도 작업이며 웹 GET은 모델을 호출하지 않습니다.

## ADR-05: API 공급자와 프로필

생성과 임베딩은 API 공급자와 작은 포트/어댑터를 사용합니다. 2026-10-27 사용자가 승인한 Docling 문서 처리와 CrossEncoder 재정렬은 별도 로컬 런타임에서 실행하며 생성·임베딩 모델의 대체 경로로 사용하지 않습니다. OpenAI Responses의 실제 output_text.delta를 사용합니다. `store:false`를 요청하지만 이를 공급자 전체 데이터 처리 정책/계약의 대체물로 해석하지 않습니다.

사용자가 모델명을 정정한 후 생성 모델 기본을 `gpt-6-luna`, effort를 명시적인 `medium`으로 정했습니다. 제공 계정의 실제 응답에서 같은 모델·effort와 `default` service tier를 확인했습니다. 실행 모드는 여전히 기본 `disabled`이며 서버 키와 `live` 설정을 해야 외부 API를 호출합니다. 위키/분석·Extended를 바꿔도 모델·effort는 바뀌지 않습니다. 공급자 반환값과 요청값은 구분하며 알려지지 않은 사용량·비용은 null입니다.

GPT-6 Luna의 확인된 Standard 텍스트 요금으로 추정 가능한 호출만 비용을 계산합니다. 캐시 쓰기 TTL은 `30m`을 요청하고 공급자의 실제 캐시 읽기/쓰기 토큰을 구분합니다. 취소 등으로 최종 usage가 없거나 모델·tier·캐시 수명 근거가 부족하면 0으로 만들지 않습니다. [실제 사용량 기록](verification/live/usage-ledger.json)은 청구서가 아닙니다.

임베딩은 사용자 결정대로 OpenAI small/large만 비교했습니다. 평가 결과 large 1536차원 축소 프로필을 초기 후보로 두되 모든 문항에서 우세하다고 주장하지 않습니다. 고정 평가 24개 답변 가능 질문의 all-facets@5는 필터 적용 후 small 17/24, large 18/24였습니다. 관점 4문항에서는 small 2/4, large 1/4였습니다. 이 corpus 기반 개발 평가를 독립 holdout이나 전문가 정답으로 표현하지 않습니다.

이번 구현 검증은 두 문헌 구간의 direct1536 API 응답을 추가 확인했습니다. 캐시의3072→1536과 매우 비슷하지만 완전히 같지 않아 프로필을 분리했습니다. 프로필 ID는 모델·API 차원·저장 차원·변환·버전을 포함합니다.

## ADR-06: Extended는 제한된 내부 탐색

기본 검색부터 여러 문헌을 사용합니다. Extended는 응답 모드, 모델, effort, 권한, 외부 검색 여부를 바꾸지 않습니다. 부족한 항목에 대한 추가 내부 질의와 주변 구간을 다룹니다.

**초기 예산 가정:** 추가 질의 최대 3개, 추가 탐색 15초, 본문 문맥 최대 24,000자. 실제 구현은 설정과 종료 사유·탐색 기록을 보존합니다. 이 수치가 최적이라고 평가하지 않았습니다. 충분성 판단은 확인한 근거 범위와 연결되어야 하며 단순 키워드 존재를 의미적 검증 통과로 표시하지 않습니다. 시간/호출/문맥 예산, 신규 근거 없음, 취소에 따라 종료합니다.

실제 부족 근거 질문에서 v1이 일반적인 조건 단어를 충분한 근거처럼 취급해 조기 종료한 문제를 수정했습니다. v2는 질문의 온도·압력·수율 등 구체 항목을 우선 계획하고, 문자열 일치는 `candidate_found`로만 기록합니다. 이 일치만으로 추가 검색을 생략하거나 의미가 충분하다고 종료하지 않습니다. 수정 후 표본은 추가 내부 질의 1회 뒤 새 근거가 없어 종료했고 온도·압력 값은 확인하지 못했다고 답했습니다. 별도 의미 충분성 판정 모델은 첫 버전에 없으며 `semanticSufficiency=not_evaluated`를 유지합니다.

## ADR-07: 일일 증분 색인 + 즉시 실행

자료 변경마다 전체 corpus를 다시 임베딩하지 않습니다. 기본은 일일 처리이고 명시적인 즉시 색인도 같은 작업 경로입니다. 입력 해시/프로필/scope가 같으면 벡터를 재사용합니다. 승인과 색인 상태를 분리합니다. 접근 철회는 즉시 적용합니다.

최신 승인 판본의 활성 포인터를 마지막에 바꿉니다. 진행 중 실패한 새 판본 때문에 기존 정상 판본이 사라지지 않습니다. 원문·구간·과거 인용은 보존하되 현재 권한이 없는 과거 답변이나 개인 위키는 표시하지 않습니다.

## ADR-08: DB 작업 큐와 실제 스트림

단일 작업자는 DB row lock과 dedupe key로 작업을 처리합니다. 취소/실패/재시도는 영속 상태입니다. API의 재연결은 재생이며 새로운 생성이 아닙니다. 본문 delta의 경계는 보존하지만 이벤트를 배치 저장해서 토큰마다 row와 commit을 만들지 않습니다.

실행 가능한 작업 중에는 색인을 파생 관계·관점 생성보다 먼저 처리합니다. 많은 메타데이터 정정이 모델 작업을 쌓아도 사용자가 요청한 검색 반영을 막지 않기 위한 순서이며, 미래 예약 작업을 앞당기거나 실행 중 작업을 선점하지 않습니다.

API 재시작 시 중단된 실행을 실패로 기록합니다. 자동 유료 재실행을 하지 않습니다. 완성된 답변을 단어로 나눠 보내던 이전 구현을 제거했습니다.

## ADR-09: 검증 가능한 추출과 검색 후보 보강

Docling은 원본 바이트와 구조·표·페이지 위치를 별도 보존하고 그 추출문에 정확히 연결되는 구간을 만든다. CrossEncoder는 여러 벡터·문자 검색 질의의 후보를 합친 뒤 재정렬하며 원문을 다시 쓰지 않는다. 선택한 실험 결과의 같은 출처에서 방법과 명시된 수치 차이의 후보를 보충하고, 관계 근거도 직접 구간과 함께 관련도를 비교한다. 원리 질문은 제한된 후보를 작용 과정 중심으로 한 번 더 살피며, 복수 항목 비교는 답변 전에 항목별 사실과 출처 ID를 별도 검토한다. 이 보강은 후보의 상대적 순위와 생성 모델에 기반하므로 동일 실험 여부, 내용의 정확성이나 충돌의 존재를 증명하지 않는다. 세부 조건과 비용·실패 처리 한계는 [아키텍처 문서](ARCHITECTURE.md)를 따른다. RAGChecker는 온라인 답변을 차단하는 판정기가 아니라 고정 질문의 전후 비교를 위한 별도 평가 도구다.

LightRAG는 동일 8문헌·94구간의 두 질문 비교에서 최종 근거와 생성 입력을 바꾸지 못했고 추가 조회 시간·비용이 들었다. 2026-10-27 사용자의 명시적 제거 지시에 따라 검색 연결·의존성·설정과 전용 DB를 제거했다. 전용 그래프 파일·격리 런타임의 파일 삭제는 자동 승인 정책에 차단돼 서비스 참조를 끊은 상태로 남아 있다. [제거 상태](LIGHTRAG_REMOVAL_20261027.md)를 따른다. 원문·판본·기존 벡터와 비교 기록은 보존한다. [소규모 비교](RAG_LIGHTRAG_SUBSET_COMPARISON_20261027.md)를 참고한다.

자료 형태와 계보는 다르다. `documentForm`은 원문·편집본·추출본을 나타내고, `lineageKey`는 검증한 동일 원자료의 여러 판본을 묶는다. 같은 제목이나 URL만으로 독립 출처 여부를 추정하지 않는다. 원본 보존과 전문 검증, 서비스 등록, 승인, 색인 완료는 각각 별도의 상태다.

추가 내부 질의에는 기존 15초 예산을 적용한다. 재정렬은 별도의 명시적 120초 제한을 사용하며 전체 검색 시간과 단계별 시간을 기록한다. 로컬 계산 비용을 공급자 호출 비용 0과 혼동하지 않고, 문헌 등록·질문·평가기 비용도 따로 기록한다. 구체적인 설치·검증 범위는 [Docling](DOCLING_INTEGRATION.md)와 최종 전후 평가 기록을 따른다.

## 아직 검증·결정해야 하는 사항

1. 운영에 사용할 계정의 데이터 처리·보관 및 계약 조건. `gpt-6-luna` 모델 결정과 실제 호출은 완료했지만 계정의 법무/계약 검토를 대신하지 않습니다.
2. 실제 모델을 사용한 답변·개인 정리·관계/관점 추출의 확대 품질 평가. 대표 사례는 실행·대조했으나 인과 조건의 압축, 인용 발언자 문맥, 개인 위키의 요약 손실이 남습니다. [의미 검토](verification/live/semantic-review.md)를 참고합니다.
3. Extended 예산의 일반적인 품질·시간·비용 효과와 조건별 질문 세트 확대. 제한된 표본 결과를 최적 예산으로 일반화하지 않습니다.
4. 실제 운영 DB·원문 저장소·권한 모델에 대한 export 대조와 대상 매핑. 현재 seed/129개 문헌이 운영 전체라는 가정은 없습니다.
5. 개인 위키 기본 자동 정리와 선택 공개 문헌의 자동 검토 후보 제출은 초기 가정입니다. 운영 사용자 피드백으로 조정할 수 있습니다.

이 미결정 항목을 이유로 위키/분석·Extended 기본값, 단일 대화, PostgreSQL, 검토자 역할 같은 확정 사항을 다시 선택하게 하지 않습니다.
